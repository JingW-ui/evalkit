# evalkit 评测系统 · 开发说明（v2）

> 通用 AI Agent 评测工具链：多 Agent 会话回看 + 批量跑测 + 统计总览 + 人工复核。
> 本文档基于当前代码（M0-M4 迭代完成）撰写，为项目开发总纲。
> 项目位置：`D:\wy_projects\evalkit`

---

## 1. 项目定位与能力

evalkit 读取 Agent 会话日志/实时事件流，回答评测核心问题：

- 有没有在对的场景加载正确的 skill / 调用正确的工具？
- 任务有没有完成（L1-L4 分级 + 验收指标判定）？
- Token / 成本多少？（官方结算价优先 + 峰谷定价估算）
- 几次人工介入、几轮对话、几个工具调用？

核心能力一览：

| 能力 | 说明 |
|------|------|
| **会话评测** | 多 Agent（claude/dsh/codemaker/airlab）会话回看：报告 / 轨迹三泳道（思维链）/ 任务工具链 / 原始日志 |
| **批量评测** | 任务定义（L1-L4 + 验收指标）→ 发起跑测（agent 二选一 + 模型 + 执行目录 + DK 设备）→ n 次重复串行 → 判级 → 落库 |
| **统计总览** | task 级聚合（SR + 均值±σ）+ agent/模型/skill/level 维度 + 筛选器 + 下钻 + 轨迹联动 |
| **人工复核** | 修正 level/success（保留自动值 + 留痕 + reset） |
| **拉起会话** | 打开交互式终端（claude/codemaker），复用 agent+模型+目录配置 |
| **评测矩阵** | agent × L1-L4 成功率画像 |

## 4. 核心概念

### 4.1 统一事件流（DSH SessionEvent 同构）

| type | 含义 |
|------|------|
| `user/message` | 用户输入（真实指令，排除系统注入） |
| `assistant/message` | 模型回复（text/reasoning + usage + model） |
| `assistant/chunk` | 流式增量（TTFT 检测） |
| `tool/call` / `tool/result` | 工具调用 + 结果（callId 配对） |
| `turn/start` / `turn/end` | 轮次边界（结束原因 kind） |
| `step/start` / `step/end` | 模型活跃段（llm_ms 累计） |
| `request/header` | 会话初始化（工具列表/模型名） |
| `todo/write` | 子任务快照 |

### 4.2 任务 Task（L1-L4 + 验收指标）

```jsonc
{
  "task_id": "uu_remote_L1_001",
  "level": "L1",              // L1 单一动作 / L2 动作组合 / L3 完整闭环 / L4 诚实度
  "skill_expected": "uu_remote",
  "query": "查一下 UU 远程是否安装",
  "repeat": null,             // 任务级重复次数（null 用批次级）
  "success_condition": {      // 验收指标（校验器注册表）
    "type": "evidence_anchor",
    "anchors": ["UU", "GameViewer"],
    "threshold": 1
  }
}
```

**校验器注册表**（`parser.py` VALIDATORS）：

| type | 判定 | 适用 |
|------|------|------|
| `evidence_anchor` | 命中锚点 ≥ threshold | L1/L2/L3 |
| `negative_honesty` | 诚实失败且未伪造成功 | L4 |
| `file_exists` | 产物文件存在 + 子串 | 产物类 |

### 4.3 执行 Execution

一次任务的单次跑测 = 一条 execution（`(task_id, run_idx, model)` 定位），是统计与下钻的原子单元。

## 5. 指标总览

### 5.1 单次执行指标（EventMetrics snapshot）

| 指标 | 字段 | 说明 |
|------|------|------|
| 结果 | `success` | 任务成功布尔（校验器判定） |
| 判级 | `level` / `level_source` | L1-L4 + 来源（task/auto/manual） |
| 耗时 | `duration_ms` | 首末事件差；`llm_ms`/`tool_ms`/`human_wait_ms` 拆分 |
| 成本 | `cost_cny` | 官方 `cost_usd`（claude total_cost_usd / codemaker step_finish.cost / airlab cost）×7.2；缺失用估算 `cost_est_cny` |
| 工具 | `tool_calls_total` / `tool_success` / `tool_fail` | 调用总数 / 成功 / 失败（成功率 = success/(s+f)） |
| Token | `input_tokens` / `output_tokens` / `cache_read_tokens` | 用量 |
| 人工介入 | `human_interventions` | AskUserQuestion/question 等计数 |
| 结束原因 | `turn_end_reason` | completed/error/interrupted/... |

### 5.2 统计聚合口径（统计总览）

按 `(task_id, skill, level, agent, model)` 分组聚合 n 次执行：

| 指标 | 聚合方式 | 方差 |
|------|----------|------|
| **成功率 SR** | 成功数 / n | **否**（0/1 二项，不统计方差） |
| **耗时** | 均值 | **σ**（样本标准差） |
| **成本** | 均值 + 总和 | **σ** |
| **工具成功率** | 均值（[0,1] 连续值） | **σ** |
| **工具次数** | 均值 | **σ** |
| **Token** | 均值 | **σ** |
| **人工介入** | 均值 | 否（计数类） |

波动统一显示「均值 ± 标准差 σ」；n=1 时 σ 为空（显示单值）。

## 6. 功能模块

### 6.1 会话评测（多 Agent 回看）

- **来源**：`~/.claude/projects`（交互式 claude）、`results/board`（单任务落盘）、`results/batch`（批量跑测，标 `source=batch`）、samples、codemaker DB。
- **展示**：报告（指标）/ 轨迹三泳道（input/model/tools 时间线 = 思维链）/ 任务工具链 / 原始日志。
- **通道适配**：claude stream-json（`ClaudeEventAdapter`）、DSH（SDK）、codemaker（`CodemakerEventAdapter` + CLI）、airlab（`scan_airlab_log`）、claude JSONL 尾随（`claude_jsonl_to_events`）。
- **关键约定**：批量跑测会话优先用 `session.jsonl`（统一事件流）回看，`raw.jsonl`（stream-json）仅兜底。

### 6.2 批量评测

- **任务管理**：SQLite `tasks` 表 CRUD + `task_gen` 按 skill 一键生成 L1-L4 + 前端编辑（含验收标准结构化表单）。
- **发起参数**：agent（claude/codemaker 二选一）+ 模型（`codemaker models` 动态列表）+ 执行目录（`.mcp.json` + `.claude/skills`）+ DK 设备（token/group 拉取，带空闲状态）+ 重复次数 n + 权限模式。
- **执行**：严格串行 `for task: for i in range(n)`，每次跑测 `--no-session-persistence`（不写 `~/.claude/projects`，避免重复记录），落盘 `session.jsonl` + `raw.jsonl`。
- **进度**：SSE `batch-progress` 帧 + `/api/batch/status`。

### 6.3 统计总览

- 核心 9 列：`任务 | agent | 模型 | skill | L | n | 成功率 | 耗时(均值±σ) | 成本¥(均值±σ)`。
- 筛选器：agent / skill / level / model。
- 下钻：点 task 行 → 展开该 task+model 的 n 次执行（次要指标：工具成功率/次数/人工介入/Token）→ 每行「轨迹」跳会话评测三泳道 / 「复核」修正。
- 只统计 `task_id` 非空的记录（批量跑测），单会话评测杂数据不混入。

### 6.4 人工复核

- `PATCH /api/executions/{id}`：修正 `level`/`success`（保留 `level_auto`/`success_auto`），留 `review_status`/`review_note`/`reviewed_at`，支持 `reset` 回自动值。
- 统计用修正后的最终值。

### 6.5 拉起会话（合并到批量评测）

- 「打开交互终端」按钮：复用当前 agent+模型+执行目录，新窗口打开交互式 claude（`claude`）/ codemaker（`run -i`）。
- 终端列表折叠区（底部）+ 停止。
- 执行目录「浏览」按钮（文件选择器）。

### 6.6 评测矩阵

`agent × L1-L4` 成功率画像 + 会话明细（`matrix()`）。

## 7. 数据模型（SQLite）

### executions（每次执行一条，session_id 主键）

```sql
CREATE TABLE executions (
  session_id TEXT PRIMARY KEY, run_id TEXT, task_id TEXT, run_idx INTEGER,
  agent TEXT, model TEXT, skill_expected TEXT,
  level TEXT, level_source TEXT, level_reason TEXT,
  success INTEGER, success_by TEXT,
  tool_calls_total INTEGER, tool_success INTEGER, tool_fail INTEGER,
  input_tokens INTEGER, output_tokens INTEGER, cache_read_tokens INTEGER,
  cost_cny REAL, duration_ms INTEGER, human_interventions INTEGER,
  turn_end_reason TEXT, query TEXT,
  level_auto TEXT, success_auto INTEGER,
  review_status TEXT DEFAULT 'unreviewed', review_note TEXT, reviewed_at INTEGER,
  _at INTEGER
);
```

- 同 session 覆盖语义（`INSERT OR REPLACE`）；但**单会话评测（`_record_eval`）不覆盖已有 task_id 的批量跑测记录**（避免丢失 task 归属）。
- 老库列变更走 `_migrate()` 幂等 `ALTER TABLE ADD COLUMN`。

### tasks（任务定义，task_id 主键）

```sql
CREATE TABLE tasks (
  task_id TEXT PRIMARY KEY, level TEXT, skill_expected TEXT,
  query TEXT, repeat INTEGER DEFAULT 1,
  success_condition TEXT,  -- JSON 串
  note TEXT, created_at INTEGER, updated_at INTEGER
);
```

## 8. 关键实现

### 8.1 峰谷定价（cost.py）

DeepSeek 2026-08-17 起峰谷定价（`conf.json`）：

- `peak_hours: [[9,12],[14,18]]`（北京时间高峰），`peak_multiplier: 2.0`（高峰价=空闲×2）。
- `models_usd` 里 deepseek-v4-flash/pro 存 `offpeak`/`peak` 两档；`anchor_per_1m` 存空闲锚点。
- `estimate_cost_usd`/`anchor_unit_cost` 按当前时段自动选价。
- 成本优先级：**官方 `cost_usd`（平台结算）> 挂牌价估算（`estimate_cost_usd`）**。实测官方 ≈ 挂牌价 ×2.4（codemaker 平台加价）。

### 8.2 多后端统一

三后端（claude/dsh/codemaker）都产出统一事件流喂 `EventMetrics`；claude 通道官方值（`total_cost_usd`/`ttft_ms`/usage）从 `result` 行直取；codemaker CLI 的 `step_finish.tokens` 为累计值（只在最终 stop 回合带 usage，避免双计）。

### 8.3 会话发现与轨迹联动

- `discover_all` 合并 projects / session_root / batch_root / samples / codemaker，批量会话标 `source=batch`。
- 统计总览「轨迹」按钮 → 切会话评测 + 选中该 session + 进轨迹 tab（三泳道思维链）。

### 8.4 判级

`judge_eval`（eval_records.py）：query 匹配 task → 校验器判定；未匹配 → L4 启发式 → `classify_level` 规则兜底；结束原因兜底 success。

## 11. 运行方式

```bash
# 看板
python eval_server.py --port 8090 --web webui/dist --batch-root results/batch

# 批量跑测（CLI）
python eval_batch.py gen --domain uu_remote --out tasks/gen
python eval_batch.py run --tasks-dir tasks/gen --skill uu_remote --repeat 2 \
    --backend claude --permission-mode bypassPermissions --model deepseek-v4-flash

# 测试
python tests/test_eval_store.py && python tests/test_eval_stats.py && ...（逐个）

# 前端开发
cd webui && npm install && npm run build
```

浏览器打开 `http://127.0.0.1:8090`：会话评测 / 批量评测 / 评测矩阵 / 统计总览。
